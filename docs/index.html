Install

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/tigercosmos/code-cortex-mcp/main/install.sh | bash

# Windows (PowerShell)
Invoke-WebRequest -Uri https://raw.githubusercontent.com/tigercosmos/code-cortex-mcp/main/install.ps1 -OutFile install.ps1
.\install.ps1

# Restart your agent, then say:
"Index this project"

The installer configures Claude Code, Codex CLI, Gemini CLI, Zed, OpenCode, Antigravity, Aider, KiloCode, VS Code, Cursor, OpenClaw, Kiro, and Junie: MCP server entries, instruction files, and pre-tool hooks. One static binary for macOS, Linux, and Windows. No Docker, no Node, no Python, no API key. All data stays on your machine in ~/.cache/code-cortex-mcp/.

How it works

You: "find the call path from ReceiveOrder to SaveOrder"
Agent: trace_path(function_name="SaveOrder", from_function="ReceiveOrder", direction="inbound", max_work=10000)
Engine: returns one bounded path and explicit result-state fields
Agent: explains the call chain in plain English

The engine parses every file with tree-sitter, resolves calls and types (LSP-style hybrid resolution for Go, C, C++, TypeScript/JavaScript, Java, Kotlin, Rust, Python, PHP, and C#), and stores the graph in SQLite. A persistent worker process answers warm graph queries in 0.1–0.5 ms on the measured graph. Complete agent tasks include startup, retrieval, and model execution.

Scale architecture

AreaPrevious pathCurrent bounded path
Extraction stateFull file results remained in memory through resolution.CBM_RESULT_STORE=1 stores full results in temporary storage and retains compact summaries.
Known call chainA broad trace could explore unrelated callers.from_function searches forward from the known entry point.
Traversal stateDepth and output limits did not identify exhausted search work.max_work, path_found, and traversal_truncated expose the bound and outcome.
Release checkMCP initialization started a background check.CBM_UPDATE_CHECK=0 disables it for sealed runs.

Temporary extraction storage is run-local and not durable. The memory budget is a soft back-pressure target, not a hard resident-memory limit. The result store has a 64 GiB per-run limit and needs sufficient free space on the system temporary volume. An ENOSPC store-write failure cancels the run; free space before retrying. Features

155 languages

Vendored tree-sitter grammars compiled into the binary. Type-resolved call graphs for 10 languages; structural parsing for the rest.

Static analysis

Import-aware, type-inferred call graph. Dead code, Leiden clusters, circular dependencies, complexity metrics, git-diff blast radius.

Deterministic indexing

Two runs over the same tree produce the same nodes, edges, IDs and properties, byte for byte, whatever order the workers finish in. Verified on eleven repositories. Diff two snapshots and only real code changes show up.

Crash isolation

A supervisor contains per-file crashes and hangs during indexing. A persistent worker answers tool calls with a per-tool deadline.

Bounded scale path

An optional result store moves full extraction state to temporary storage. Compact summaries remain in memory for resolution.

Directed endpoint traces

from_function and max_work bound known call-chain searches. Result fields distinguish no path from truncated work.

Preprocessor-aware C/C++

Recovers definitions split across #ifdef branches. Headers get their own File nodes with resolved #include edges.

Code search

BM25 full text (FTS5), structural search, and semantic similarity edges from algorithmic embeddings. No API key.

Cross-service links

HTTP route ↔ call site; gRPC, GraphQL, tRPC; Socket.IO and pub-sub channels; CROSS_* edges across repositories.

Team artifact

Commit .code-cortex/graph.db.zst and teammates import the graph instead of a full reindex. A merge=ours rule prevents conflicts.

Compared to codebase-memory-mcp

code-cortex-mcp forked from DeusData/codebase-memory-mcp and keeps its on-disk graph format. Historical cold-index and warm-tool measurements show lower times for most measured operations. The complete-task table above measures the newer agent-task boundary. codebase-memory-mcp retains features that this fork omits.

Measured 2026-08-25 on an Apple M3 Max (14 cores, 36 GB) and a 32-core Linux machine (62 GB): code-cortex-mcp at af4579de plus the llvm-project crash fix, codebase-memory-mcp at 010569fa, each built with its own scripts/build.sh, from an empty cache.
